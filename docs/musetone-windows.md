# MuseSync 谱伴同步 for Windows

当前发布版：**2.5.5**，同步组件：**MuseSync Bridge 1.4.0**。

原名 MuseTone。从 2.3.0 起，VST3 文件夹和内部模块已统一为 `MuseSync.vst3`。
VST3 类 ID、参数状态、安装器身份及 `MuseToneSync` 同步路径保持不变。
升级会将旧 VST3 副本归档停用，避免重复扫描；不必手动改名。

## 下载与启用

普通用户下载 `MuseSync-Setup-2.5.5-Windows-x64.exe`，核对同一发布页的
`SHA256SUMS.txt` 后安装。此 EXE 是安装器，不是独立播放器。
需要 Windows 10/11 x64、官方 MuseScore 4 安装版，以及 Microsoft Edge WebView2 Runtime；安装前保存谱面并退出 MuseScore。分发时只需发送 EXE，对方无需源码或 ZIP，但仍需安装宿主并启用插件。Windows 11 通常已预装 WebView2 Runtime；若视频窗口提示缺少运行时，请从微软官方渠道安装 Evergreen WebView2 Runtime。

MuseScore 3 不支持 VST3，因此不支持本插件。4.0–4.5 已增加旧版 Qt 5 设置读写、数值型时间接口及多声部速度扫描兼容；4.6–4.7 保留新版分段路径。两套接口均有回归测试，但尚未逐个版本实机验证，不能保证所有 4.x 构建。旧版在音符之间的速度标记、渐变速度、反复和播放倍率方面仍可能偏移，推荐较新的官方 4.x。多个 4.x 共存时，Bridge 只安装到向导所选版本，换用其他版本需重新选择目录安装。

安装时选择包含 `bin\MuseScore4.exe` 的 MuseScore 目录，支持其他盘符。
安装器会同时部署 VST3 和 Bridge。重启后在插件管理中启用 `MuseSync Bridge`，
每次会话从插件菜单运行一次，出现已开启提示后可以关闭提示，后台同步仍继续。
在混音器的 VST3 音源列表选择 `MuseSync`，保持该通道未静音，然后载入伴奏。

安装器未签名，可能触发 SmartScreen，请确认来源并遵循本机安全策略。
安装器为 Sync 自身文件夹配置用户写入权限，以保存同步快照，其他插件目录不受影响。
程序说明和卸载入口位于 `C:\Program Files\MuseTone`。卸载前退出 MuseScore，
再从 Windows 设置的应用列表卸载；用户谱面、音频和其他插件不会被删除。

## 更新与覆盖安装

需要卸载后重装时，先保存谱面并退出 MuseScore，再双击安装包旁的 `Uninstall-MuseSync.vbs`（同目录的 PS1 文件也要保留），允许管理员权限并确认。
安装目录内也有 `一键卸载 MuseSync` 快捷方式。入口会移除 MuseSync Bridge、MuseSync/MuseTone VST3 及验证过身份的旧版停用文件，保留谱面、音频、其他插件和同步 INI 设置。
它不会强制关闭 MuseScore；文件被占用时会提示关闭软件后重试。卸载完成后可直接重新运行安装 EXE。

2.3.0 起，在打开插件面板后会后台检查正式发布版本；发现新版时，“？”按钮出现提示点。
打开“？”使用指南，在底部可查看当前版本、点击“检查更新”，以及“下载更新”。
安装器直接在插件内下载，显示进度并支持取消，下载完成后自动核对 SHA-256。
通过校验后按钮变为“安装更新”，确认后打开安装器，不跳转浏览器，不自动关闭 MuseScore。
检查或下载失败可重试；没有后台常驻服务，关闭插件面板会取消尚未完成的任务。
更新请求只访问 GitHub 发布下载地址，不需要 GitHub 登录，不上传谱面或伴奏。
下载保存在 `%LOCALAPPDATA%\MuseSync\Updates`；校验失败的临时文件会删除。
2.2.0 及更早版本没有此更新入口，需要先手动下载 EXE 升级到 2.3.0。

也可以到 [GitHub 发布页](https://github.com/Aigooz/MuseSync/releases/latest)手动下载新版
`MuseSync-Setup-版本号-Windows-x64.exe` 并核对 `SHA256SUMS.txt`。

1. 保存谱面，退出 MuseScore 及其他正在使用该插件的宿主。
2. 直接运行新版 EXE，无需先卸载旧版。
3. 安装器沿用上次安装位置，覆盖 VST3 和 Bridge，并更新同一个卸载入口。
4. 重启 MuseScore，运行 MuseSync Bridge 后继续使用；若列表仍显示旧名称，重新扫描 VST3。

升级不会替换你的谱面、伴奏文件和 Bridge 的现有 INI 文件；已随谱面保存的插件参数仍由谱面保存。
如果 MuseScore 已搬到其他目录，请在安装时选择新的目录。
从 MuseTone 升级时会自动归档停用旧名称的插件，无需手动卸载或改名。

## 功能

导入音频或本地视频后，插件会在后台分析音轨，在波形／视频上方显示当前位置的“素材 BPM”及分段变化曲线。点击曲线可以跳转位置。本地视频的音轨通过 Windows Media Foundation 解码；缺少相应音频解码器时会显示分析失败，视频播放仍可继续。

分段识别采用 [MiniBPM](https://github.com/breakfastquay/minibpm)，使用 8 秒重叠窗口，每 1 秒计算一段。分析完成后，播放和暂停跳转均会显示对应位置的估计值；分析在后台运行，不占用宿主音频回调。静音、持续单音或不足 4 秒的片段可能显示“未识别”。素材关闭或更换时会取消旧任务并清空旧结果。

在线视频不进行素材 BPM 分析。音频和本地视频显示的是素材原始速度的估计 BPM。

识别范围设置为 45–240 BPM，快速变速会受到窗口平滑影响，复杂节奏仍可能出现半速／倍速判断。该数值用于观察素材速度，不会自动修改谱面速度、手动 BPM 或同步对齐关系；音频节拍到谱面小节的自动匹配仍需另行实现。

Windows 版可从插件“打开”菜单载入 MP4、WebM、M4V 本地视频，或输入 http/https 视频网页地址。视频在独立、可调整大小的窗口播放，并跟随 MuseScore 谱面播放头：播放、暂停、谱面跳转和插件进度条跳转都会同步；谱面速度变化也会按谱面时间轴校正视频位置。网页播放器只有在页面提供可访问的 HTML5 `<video>` 时才能被同步控制；Bilibili 等网站还可能受登录、iframe、地区、版权或网站策略限制。WebView2 使用独立浏览器配置，可能需要在视频窗口内单独登录。播放器需要 Microsoft Edge WebView2 Runtime；此功能不下载网络视频。音频伴奏仍通过原有音频入口载入。

MuseSync 是 Windows VST3 插件，保留音频载入、波形、拍号网格、偏移和宿主时间轴同步，并增加：

- 半音：`-24` 到 `+24`，用于整曲移调。
- 音分：`-100` 到 `+100`，用于细微校音。
- 半音和音分可以同时设置，实际比例为 `2 ^ ((半音 * 100 + 音分) / 1200)`。
- 变调在后台线程完成，不阻塞实时音频回调。
- 变调结果保持原采样率、声道数、帧数和总时长。
- 面板获得焦点时按空格，会向宿主根窗口转发播放/暂停按键。

空格同步依赖宿主窗口接收空格快捷键。若宿主或 MuseScore 没有把焦点交给可处理播放命令的窗口，插件无法替宿主决定播放行为。

## 构建

需要 Visual Studio 2022 Build Tools、CMake 和 VST3 SDK：

```powershell
git clone --recurse-submodules https://github.com/steinbergmedia/vst3sdk.git vst3sdk
cmake -S . -B build-musetone-live -G "Visual Studio 17 2022" -A x64 -DVST3_SDK_DIR=.\vst3sdk
cmake --build build-musetone-live --config Release --parallel
```

发布版固定 VST3 SDK 提交 `3cdf9ca5d1f5b1b21e0a86832aa4abe55607bd96`，
SDK 子模块需完整。安装 Inno Setup 6 后，用 PowerShell 7 打包：

```powershell
pwsh -File tools/package-windows.ps1 -BuildDirectory build-musetone-live
```

生成 EXE、便携 ZIP、包含 SDK 的完整对应源码 ZIP、发布说明和 SHA256 校验文件。
Windows 使用静态 MSVC 运行库，无需单独安装 VC++ Redistributable。

VST3 bundle 通常位于：

```text
build-musetone-live/VST3/Release/MuseSync.vst3
```

标准安装目录为：

```text
C:\Program Files\Common Files\VST3\MuseSync.vst3
```

## 与原版共存

原版 `DaweiDrumScore.vst3` 和原版安装器在本地整理时归档到 `待清理-历史文件/dist/windows`，新版产物使用不同 bundle 名称和 UID，目标输出位于 `dist/windows-musetone`，不会覆盖原版文件。安装新版后，MuseScore 里显示为 `MuseSync`。从 MuseTone 升级保留相同 UID 和工程状态，将旧 bundle 归档为不可扫描的备份。

## 当前工程同步

部署脚本同时安装 `MuseSync Bridge` 到 MuseScore 的 plugins 目录。重启 MuseScore 后，
在插件管理中启用它，并在每次 MuseScore 会话中从插件菜单运行一次。
它在后台读取当前打开谱面的速度表、拍号和中途变化，不需要手动导入或保存谱子。
VST3 的「当前谱面」按钮可刷新连接；没有信息时保留默认网格并标注来源。
当前桥接只面向同一安装下单个 MuseScore 进程。MT3 快照读取每小节的
`timesigActual` 实际时值，支持弱起和不完整小节；显示编号使用 `no + 1`，
与内部连续小节索引分开。MuseScore 布局已将 `noOffset` 计入 `no`，不能重复叠加。
旧版 API 缺少实际时值时回退到标称拍号。
网格按速度表分段换算，包括小节内变速；BPM 和拍号框跟随当前播放位置。
进度条右侧及收起后的悬浮条显示「小节-拍数」，例如 `73-3`。
拍数以拍号分母计数，6/8 显示 1 至 6。反复展开和临时播放速度倍率仍有限制，
不自动拉伸伴奏音频。关闭「跟随谱面」后，手动速度与拍号设置保持独立。

## 悬浮窗口与主题

右上角收起后保留可拖动悬浮条，显示播放状态、时间和小节拍数。
展开按钮尽量与收起时的点击位置对齐，点击展开图标或双击悬浮条恢复完整面板。
收起不会停止音频。视频小窗在进度条下方提供音量滑块、延迟输入框和加减按钮，与完整面板共享设置。
新实例默认深色主题，已有工程明确保存的主题继续沿用。主题菜单提供九种配色，指南、波形和悬浮条同步使用主题。
问号按钮打开内置指南，「关于」区以小字标注 `@爱鸽咕子`。

## 音量、偏移与跳转

- 底部采用等宽的同步与移调两区，BPM、拍号、半音和音分输入框对齐；
  音量收为移调区下方的一行滑条，不再单独占一整栏。
  参数区减高 18 个逻辑像素，留给波形显示；宽窗口下限制参数区最大宽度，避免控件拉得过散。
- 拍号框的闭合外观跟随九种主题，下拉列表与键盘操作仍使用原生控件。
- 音量使用横向滑条，支持点击定位、拖动、滚轮和方向键，范围为 `0` 到 `100%`。
  百分比仅用于显示，不再需要输入数字。
- 起始偏移可直接输入毫秒，支持正负值，范围为 `-3600000` 到 `3600000 ms`。
  回车或离开输入框后应用；Ctrl / Alt 拖动波形时数值实时更新，Shift 可微调。
- 起始偏移增加 `-` / `+` 按钮和滚轮调节，默认每格 `10 ms`，按住 Ctrl 时为 `100 ms`，按住 Shift 时为 `1 ms`。
- 延迟、BPM、半音和音分输入框禁止输入空格或粘贴含空白的数值，按回车提交时不再触发系统提示音。
- 半音、音分和手动 BPM 输入框支持滚轮，保留高精度滚轮的不足一格增量。
  半音和音分输入有效整数后立即请求变调，不需要先点击其他控件。
- 普通单击波形向新版 `MuseSync Bridge` 请求谱面跳转并开始播放；拖动仍平移视野。
  跳转先扣除起始偏移，再选择对应时间之前最近的音符或休止符，交由 MuseScore 播放。
  不单独启动伴奏，伴奏继续跟随宿主时间轴，避免两边不同步。
- 跳转使用 `MuseToneCommands.ini` 请求通道，并校验当前谱面 session 和请求有效期。
  需要启用并运行新版 `MuseSync Bridge`；优先使用 MuseScore 光标的谱面时间，
  旧接口回退到按速度积分。反复展开、临时播放速度倍率和旧接口下的变速仍有精度限制。

## 变调实现说明

音频文件解码后保存一份不可变原始快照。后台使用 Signalsmith Stretch 1.0.0
进行保持时长的变调，补偿算法延迟后发布结果，不改变谱面同步时间。
修复了原后台任务未记录算法成功返回值、导致非零移调结果始终无法发布的问题。

参数连续变化时先合并 90 ms 内的调整，再开始计算；旧任务按音频块取消，
以 generation 标记防止覆盖最后一次设置。处理时显示进度，恢复原调直接复用
原始快照，无需再次计算或复制整曲。长音频仍需后台处理，不是实时移调。
依赖源码、版本来源及 MIT 许可证位于 `source/third_party/signalsmith-stretch`。

## REA 静态分析边界

已对原 Windows PE 产物执行静态检查：PE32+ x64、导出入口、导入库和 Win32/Media Foundation/输入消息相关 API 均已记录。该环境没有可用的 REA MCP、IDA、Ghidra 或 Hopper，因此这是基于 PE 表和源码的静态分析，不等同于运行时追踪、动态调试或完整反编译；静态导入也不能单独证明某个 API 在每次运行中都会被调用。
